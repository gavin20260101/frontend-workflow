# 无人值守任务书的格式

`/unattended` 读取、`/unattended-plan` 生成的任务书都按这个格式。修改格式时两个技能要一起看。

可以用 `/unattended-plan <要做的事>` 生成，也可以复制下面的模板自己写。保存成 `.md` 文件，放在 git 不跟踪的目录（如本机忽略的 `docs/plans/`），然后运行 `/unattended <文件路径>`。

运行前确认两件事：工作区是干净的（自己的改动先提交或收起）；权限模式是“自动”。

## 模板

```markdown
# 无人值守任务计划

## T1 <一句话标题>
- 类型：feature            # feature | bugfix | implement | test | other
- 输入：<需求原文、问题描述，或方案文件路径>
- 依赖：无                 # 无 | T1, T2

## T2 ...
```

可选的行，需要时才写：

- `隔离：是`：这个任务在单独的子会话里做（任务很大、想要干净的上下文时用）。一次运行最多 6 个。
- `备注：……`：你想事先交代的偏好或限制，比如“不要新增依赖”“只改 base 主题”。无人值守时会照着做。

整份任务书的设置，写在标题下面、第一个任务之前，需要时才写：

- `用量上限：95`：5 小时窗口、每周全部模型、每周单个模型，任何一个的用量达到这个百分比就停下，不再开始新的任务。不写就是 95。停下后不会自己恢复，窗口重置后重新运行。只在 Claude 桌面应用里能查到用量。

## 类型说明

| 类型 | 做什么 | 输入写什么 |
| --- | --- | --- |
| feature | 插件 `req-analysis --auto` 出方案，接着 `req-implement --auto` 实现 | 需求原文 |
| bugfix | 插件 `req-bugfix --auto` 复现和定位，接着 `req-implement --auto` 修复 | 现象、复现步骤、期望结果、环境 |
| implement | 插件 `req-implement --auto` 按已有方案实现 | 方案文件路径 |
| test | 插件 `req-test --auto`，只测试、不改业务代码 | 需求原文或方案路径 |
| other | 不走插件，直接做（文档、文案、不影响运行行为的配置）；不经过测试和审核，会改业务源码或规则配置的写成 feature | 要做的事 |

每个任务做完并核验通过后，各提交一次到 `auto/<日期时间>` 分支。失败的任务不提交，改动收进 stash；依赖它的任务跳过，其余继续。`test` 任务发现缺陷不算失败：抓到缺陷的测试收进 stash，测试报告照常保留。

## 怎么写更容易成功

没有人能回答问题，歧义都会变成“按假设处理”。所以：

- 需求写清楚验收条件（“当……时，应该……”）。
- 缺陷写清楚复现步骤和期望结果；复现不了的缺陷会直接终止，不会猜根因。
- 涉及验证码登录、支付、真机的部分做不了，会记为“未执行”并转成手工步骤。能用测试账号登录的页面，离开前在可见 Chrome（browser-chrome）里登录一次，`备注` 里写“登录：用可见 Chrome 已保留的登录态”；不要把账号密码写进任务书。

## 示例

```markdown
# 无人值守任务计划

## T1 首页“更多”面板加分享入口
- 类型：feature
- 输入：首页“更多”底部面板里加一个“分享”入口，点击后打开 ShareSheet，渠道为复制链接和保存图片。只在 canShare 为真时显示。
- 依赖：无

## T2 会员中心金额在 iOS 上换行
- 类型：bugfix
- 输入：会员中心余额超过 6 位时在 iOS Safari 换成两行。复现：打开 /member，余额 1234567。期望一行显示。必现。
- 依赖：无

## T3 更新真机测试步骤
- 类型：other
- 输入：把 T1 的分享入口补进 docs/acceptance/manual-device-tests.md 的全量冒烟。
- 依赖：T1
```
