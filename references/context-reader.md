# 读取参考项目和设计图

需求涉及另一个项目的源码（“参考 xx 项目的做法”“和 xx 那边保持一致”），或附了 UI 设计图时，要读的东西多就交给 `req-context-reader` 子代理去读，不要在主会话里自己通读；只看几处已知位置时自己读。判断标准见下一节。

原因：主会话每推进一步都要重读前面的全部对话。几十个源码文件或一张设计图读进来，之后的每一步都要带着它们，用量成倍放大。子代理读完写成文件，主会话只收到几行要点；子代理默认用 Sonnet，单价也更低。

## 什么时候派、什么时候自己读

按要读多少、怎么找来判断，不按文件个数：

- **自己读**：要看的位置已经知道（需求或项目文档点名了文件、函数），只读这些位置的局部，合计几百行以内。用 `sed -n` 或 Read 的行号范围读需要的那几段，不读整个文件。派子代理要多一份它读规则、读需求的固定开销，这种情况下反而更贵。
- **派子代理**：需要在参考项目里搜索才知道在哪；要通读一个模块或一批文件；要沿调用链跨好几个文件追下去；或者预计要读的内容超过一千行。
- **设计图**：派。图片和画板文件读进主会话就是一大块，而且要整理成规格才能用。例外：项目里已经有整理好的视觉规格、而且覆盖了本次涉及的页面时，直接读规格里相关的那几节，不用派。
- 读到一半发现比预想的多（找到的位置又牵出一串文件），停下来把剩下的问题交给子代理，已经读到的结论写进问题里，不要接着自己读下去。

自己读时，方案“参考资料”照样写清读了哪些文件的哪几行，并注明“主会话直接读，未派 req-context-reader”。

## 什么时候不派

- 当前项目自己的代码：照常由主会话定位，不交给它。
- 判断类的问题（要不要照搬、那边做得对不对、方案选哪个）：留给主会话，子代理只负责把事实找出来。

## 调用前

1. **定好报告路径**：`docs/plans/context/<方案文件名去掉 .md>-<序号>.md`。方案文件名按“保存方案文件”一节的规则先定下来，保存方案时用同一个名字。写入前按 `${CLAUDE_PLUGIN_ROOT}/references/plan-file.md` 的“会不会被提交进仓库”确认 `docs/plans/` 会被忽略。
2. **参考项目的路径和版本**：
   - 路径不在当前工作目录内时，子代理每读一个文件都可能弹权限确认。先告诉用户：请把这个目录加为额外目录（会话中运行 `/add-dir <路径>`，或写进项目 `.claude/settings.local.json` 的 `permissions.additionalDirectories`），加好后回复。
   - 由你运行 `git -C <参考项目路径> rev-parse --short HEAD` 记下参考项目的提交号（子代理不能在别的仓库运行 git），写进方案的“参考资料”。不是 git 仓库时记“无”。
3. **设计图**：只接受本机文件：图片（png、jpg、webp）、pdf，或设计工具导出的 HTML、JSON 画板文件。导出文件里有准确的数值，比看图可靠，两者都有时优先给导出文件。只给了 Figma、蓝湖、MasterGo 这类链接时，请用户导出图片或标注稿放到本机，告诉你路径；不要尝试登录这些网站。

## 怎么调用

- **问题写具体，一次问齐**：编号写出问题（Q1、Q2……）和每个问题的用途，例如“Q1：订单列表的筛选条件有哪些，各对应接口的哪个字段——用于确定本需求的 AC2”。不要写“读一下订单模块”。同一个参考项目的问题合在一次调用里，不分几次派。
- **附上当前项目的版本**：框架和主要库的版本，子代理用来判断哪些写法不能照搬。
- **选模型**：
  - 设计图规格、需要理解逻辑的源码问题（调用链、边界情况、为什么这样做）：用子代理默认的 Sonnet，不另外指定。
  - 要移植或照搬的源码涉及并发、重试、单飞、实时连接、会话令牌、加密、支付或失败关闭：把 Agent 工具的 `model` 参数设为 `opus`。这类逻辑漏读一个分支，实现照着报告写就会带上同样的漏洞，而且要到审核或真机上才暴露。
  - 只是定位和列清单（某个功能在哪些文件、用了哪些接口、有哪些页面）：把 Agent 工具的 `model` 参数设为 `haiku`。
  - 不要用 Haiku 看设计图：看图时间距、颜色、字号容易读偏，结论错了实现阶段返工更贵。
- **设计图**：提供图片路径、对应当前项目的哪个页面或组件、当前项目的设计变量文件和公共组件目录（有的话）。

## 收到报告后

1. 只读它返回的要点。需要细节时打开报告文件里的对应小节，不通读。
2. **抽查**：会写进“代码定位”“相似实现”或方案决策的结论，打开报告引用的原文核对一两处。核对不符时，在同一份报告的基础上用 SendMessage 让它更正，不新开一个。
3. 报告里的“不确定”：影响 AC 或实现方式的，写成待确认事项（Q 编号）；不影响的，在方案里注明“按 xx 处理（未确认）”。
4. 报告开头有“需要用户协助”时，请用户处理后，用 SendMessage 让同一个子代理接着做。

## 写进方案文件

方案文件加一节“参考资料”，供新开会话的 /req-implement 找到这些资料：

- 每份报告的路径和一句话主题；
- 参考项目的路径和提交号；
- 设计图文件路径，以及对应的规格报告路径。

没有参考项目和设计图时，这一节写“无”。

## 无人值守（`--auto`）

- 参考项目在工作目录外、读取被权限拒绝时，不等用户：在无人值守记录里写明“未能读取参考项目：原因”，方案的“参考资料”写“未读取（权限）”，依赖它的结论按项目内能找到的证据写，证据不足的按 `unattended-mode.md` 的分类处理。
- 设计图只有链接、没有本机文件时同样处理：记为“未读取设计图”，页面样式按项目已有组件和设计变量实现，并列入汇总的重点复核。
